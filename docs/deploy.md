# מדריך עלייה לאוויר – PGL-R

מדריך תפעולי, שלב אחרי שלב, מהקמת החשבונות ועד יום ה-Go-Live.
סמנו כל שלב בסיום. שלבים 1–5 אפשר לבצע במקביל; משלב 6 והלאה הסדר מחייב.

**זמן משוער:** 3–4 שעות עבודה טכנית (שלבים 1–9) + יום עבודה להגירת הנתונים ובדיקות (שלבים 10–13).

## 1. Supabase – בסיס נתונים ואחסון

1. צרו פרויקט חדש. **אזור:** `eu-central-1` (פרנקפורט) – הקרוב ביותר לישראל.
2. שמרו את סיסמת בסיס הנתונים במקום בטוח. אין דרך לשחזר אותה.
3. הפעילו **Point in Time Recovery** תחת `Database → Backups`. זו דרישת פרק 2.4.
4. העתיקו את שתי מחרוזות החיבור מ-`Project Settings → Database`:
   - **Transaction pooler** (פורט 6543) ← זה `DATABASE_URL`, לשימוש האפליקציה.
   - **Direct connection** (פורט 5432) ← זה `DIRECT_URL`, לשימוש migrations בלבד.
5. העתיקו מ-`Project Settings → API`:
   - `Project URL` ← `NEXT_PUBLIC_SUPABASE_URL`
   - `service_role` key ← `SUPABASE_SERVICE_ROLE_KEY`

> ⚠️ מפתח ה-`service_role` עוקף כל הרשאה. הוא מוגדר בקוד כשרת-בלבד ואסור שיופיע במשתנה שמתחיל ב-`NEXT_PUBLIC_`.

ה-buckets עצמם ייווצרו בשלב 7 בפקודה אחת, אין צורך ליצור אותם ידנית.

## 2. Clerk – הזדהות

1. צרו אפליקציה חדשה. שיטות כניסה: **Email + Password** ו-**Google** (אופציונלי).
2. `Configure → Restrictions`: הגדירו **Sign-up mode = Restricted**. זו דרישת פרק 6.1 – אין הרשמה עצמית, משתמשים נוצרים רק בהזמנה.
3. `Configure → Multi-factor`: הפעילו **Authenticator app (TOTP)** ו-**Backup codes**.
   האכיפה בפועל היא בצד המערכת, לפי `הגדרות → אבטחה` (ברירת מחדל: MFA חובה לאדמין).
4. `Configure → Sessions`: קבעו תוקף session לפי מדיניות החברה (מומלץ 7 ימים, inactivity 1 יום).
5. העתיקו מ-`API Keys`: `Publishable key` ← `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `Secret key` ← `CLERK_SECRET_KEY`.
6. את ה-webhook מגדירים רק **אחרי** הפריסה הראשונה, בשלב 8.

> אם משתמשים ב-Google OAuth: בהגדרות Clerk הגבילו אותו כך שלא יאפשר יצירת חשבון חדש, אלא רק כניסה למשתמש שכבר הוזמן.

---

## 3. Resend – דואר יוצא

1. `Domains → Add Domain`: הוסיפו את דומיין החברה והוסיפו את רשומות ה-DNS שהמסך מציג (SPF, DKIM, ורצוי DMARC). אימות לוקח בין דקות לשעות.
2. המתינו לסטטוס **Verified**. שליחה מדומיין לא מאומת תיחסם או תיפול לספאם.
3. `API Keys`: צרו מפתח בהרשאת **Sending access** ← `RESEND_API_KEY`.
4. את ה-webhook מגדירים בשלב 8.
5. החליטו על כתובת השולח, למשל `no-reply@pgl.co.il`, ועל כתובת `reply-to` אנושית. שתיהן נכנסות לאשף ההגדרות בשלב 10.

---

## 4. Cloudflare R2 – גיבוי קבצים

1. צרו bucket פרטי, למשל `pgl-backups` ← `R2_BUCKET`.
2. `Manage R2 API Tokens`: צרו token בהרשאת **Object Read & Write** על ה-bucket הזה בלבד.
3. שמרו: `Account ID` ← `R2_ACCOUNT_ID`, `Access Key ID` ← `R2_ACCESS_KEY_ID`, `Secret Access Key` ← `R2_SECRET_ACCESS_KEY`.

אם תדלגו על שלב זה המערכת תעבוד, אך משימת הגיבוי היומית תדווח כשל.

## 5. הכנת סוד ל-Cron

צרו מחרוזת אקראית ארוכה:

```bash
openssl rand -hex 32
```

זה הערך של `CRON_SECRET`. Vercel שולח אותו אוטומטית בכותרת `Authorization: Bearer …` בכל הרצת cron, והמערכת דוחה כל קריאה אחרת ב-401.

---

## 6. Vercel – יצירת הפרויקט והגדרת משתני סביבה

1. `Add New → Project` וייבאו את הריפו `oavital77-code/PGL-R`.
2. **Framework:** Next.js (מזוהה אוטומטית). **Install Command:** `pnpm install`. **Build Command:** `next build`.
3. `Settings → Functions`: **Region = Frankfurt (fra1)**, זהה לאזור Supabase.
4. `Settings → Functions`: העלו את זיכרון הפונקציות ל-**2 GB** לפחות (או הפעילו Fluid Compute). הפקת ה-PDF מריצה Chromium ונופלת בזיכרון נמוך.
5. `Settings → Environment Variables`: הזינו את כל הערכים הבאים לסביבת **Production** (וגם ל-Preview, אם רוצים סביבת בדיקות – עם בסיס נתונים נפרד):

| משתנה | מקור | חובה |
|---|---|---|
| `DATABASE_URL` | Supabase – Transaction pooler, פורט 6543 | ✅ |
| `DIRECT_URL` | Supabase – Direct connection, פורט 5432 | ✅ |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase – Project URL | ✅ |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase – service_role | ✅ |
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` | Clerk | ✅ |
| `CLERK_SECRET_KEY` | Clerk | ✅ |
| `CLERK_WEBHOOK_SECRET` | Clerk – יתקבל בשלב 8 | ✅ |
| `RESEND_API_KEY` | Resend | ✅ |
| `RESEND_WEBHOOK_SECRET` | Resend – יתקבל בשלב 8 | ✅ |
| `CRON_SECRET` | שלב 5 | ✅ |
| `APP_BASE_URL` | כתובת המערכת, למשל `https://app.pgl.co.il` | ✅ |
| `CBS_API_BASE_URL` | `https://api.cbs.gov.il` | ✅ |
| `R2_ACCOUNT_ID` / `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` / `R2_BUCKET` | Cloudflare | לגיבוי |
| `SENTRY_DSN` | Sentry | אופציונלי |

6. `Settings → Git`: ענף הפרודקשן הוא `main`. פריסות מענפים אחרים יהיו Preview.
7. `Settings → Domains`: חברו את הדומיין והוסיפו את רשומת ה-DNS ש-Vercel מבקש. ודאו ש-`APP_BASE_URL` זהה בדיוק לדומיין הסופי, כולל `https://` וללא `/` בסוף.

## 7. פריסה ראשונה והכנת בסיס הנתונים

1. מזגו את קוד הפיתוח ל-`main` (או פרסו את הענף הנוכחי כ-Production). המתינו לסיום ה-build.
2. מהמחשב המקומי, מול בסיס הנתונים של הפרודקשן:

```bash
git clone https://github.com/oavital77-code/PGL-R.git && cd PGL-R
pnpm install
cp .env.example .env.local      # מלאו DATABASE_URL, DIRECT_URL, NEXT_PUBLIC_SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY

pnpm db:migrate                 # יצירת הסכמה, הטריגרים וה-RLS
pnpm db:seed                    # סטטוסים, שלבים, תבניות, מע"מ, מחלקות – אידמפוטנטי
pnpm storage:init               # יצירת 8 ה-buckets הפרטיים ב-Supabase Storage
```

3. ודאו שהאפליקציה חיה:

```bash
curl https://app.pgl.co.il/api/health      # {"ok":true,...}
```

> `pnpm db:migrate` ו-`pnpm db:seed` בטוחים להרצה חוזרת. הריצו אותם מחדש אחרי כל עדכון גרסה שכולל שינוי סכמה.

## 8. חיבור ה-Webhooks

עכשיו, כשיש כתובת פומבית, מחברים את שני ה-webhooks.

**Clerk:** `Configure → Webhooks → Add Endpoint`
- כתובת: `https://app.pgl.co.il/api/webhooks/clerk`
- אירועים: `user.created`, `user.updated`, `user.deleted`
- העתיקו את ה-**Signing Secret** ל-`CLERK_WEBHOOK_SECRET` ב-Vercel.

**Resend:** `Webhooks → Add Webhook`
- כתובת: `https://app.pgl.co.il/api/webhooks/resend`
- אירועים: `email.sent`, `email.delivered`, `email.opened`, `email.bounced`, `email.delivery_delayed`, `email.complained`, `email.failed`
- העתיקו את ה-**Signing Secret** ל-`RESEND_WEBHOOK_SECRET` ב-Vercel.

לאחר עדכון שני המשתנים **הריצו Redeploy** ב-Vercel, אחרת הערכים החדשים לא ייטענו.
בדקו ב-Clerk וב-Resend שהמסירה מחזירה `200`.

## 9. יצירת האדמין הראשון

1. ב-Clerk: `Users → Create user`, עם כתובת המייל של האדמין (למשל `ido@pgl.co.il`).
2. מהמחשב המקומי, מול בסיס הנתונים של הפרודקשן:

```bash
pnpm tsx scripts/bootstrap-admin.ts ido@pgl.co.il "עידו" "כהן"
```

3. היכנסו למערכת בכתובת `https://app.pgl.co.il`. בכניסה הראשונה תתבקשו להגדיר MFA (אפליקציית אימות), ואז תועברו אוטומטית לאשף ההגדרות.

> אם מופיע מסך "אין חשבון": המייל ב-Clerk אינו זהה למייל בטבלת המשתמשים. תקנו והיכנסו שוב.

## 11. הגירת הנתונים מאדמירל

במסך `ניהול → ייבוא נתונים`, לפי הסדר הזה בדיוק (התלויות בין הישויות מחייבות אותו):

| סדר | ישות | סדר | ישות |
|---|---|---|---|
| 1 | מחלקות, דרגות, שמות שלבים | 7 | תתי-חוזים |
| 2 | עובדים, עלויות שעתיות | 8 | אבני דרך |
| 3 | לקוחות, אנשי קשר | 9 | דיווחי שעות |
| 4 | ספקים | 10 | חשבונות היסטוריים + שורותיהם |
| 5 | פרויקטים | 11 | תקבולים + שיוכם לחשבונות |
| 6 | חוזים | 12 | חשבוניות ספקים |

לכל ישות:
1. הורידו את תבנית ה-xlsx מהמסך והעתיקו אליה את הנתונים מאדמירל.
2. העלו והריצו **בדיקה יבשה**. תקבלו דוח שגיאות ברמת השורה.
3. תקנו בקובץ וחזרו לבדיקה יבשה עד שאין שגיאות.
4. הריצו **ביצוע**. כל ישות נכנסת בטרנזקציה אחת: או הכול או כלום.
5. אם הישות נכנסה שגוי, אפשר לבטל את כל ה-batch בכפתור אחד.

לאחר סיום ההגירה:
- הריצו את **דוח הפערים** מול העמודות המקוריות כדי לאתר שדות שלא מופו.
- **עדכנו מחדש את המספור** (שלב 7 באשף) כך שימשיך אחרי המספר הגבוה ביותר שיובא.
- מסמכים היסטוריים (חוזים סרוקים, חשבונות ישנים) מועלים דרך טאב "מסמכים" בכל פרויקט או חוזה, בגרירה של מספר קבצים יחד. ייבוא zip כאצווה לא מומש, ראו `DEVIATIONS.md`.

## 12. יצירת המשתמשים

1. `ניהול → משתמשים`: הוסיפו כל עובד עם תפקיד, מחלקה, דרגה, תקן שעות וימי עבודה.
2. שלחו הזמנה. העובד מקבל מייל מ-Clerk, קובע סיסמה, ומשלים MFA אם נדרש לתפקידו.
3. הזינו **עלות שעתית** לכל עובד, עם תאריך תחילת תוקף. בלעדיה דוחות הרווחיות יראו עלות אפס.
4. ודאו שלכל מחלקה מוגדר מנהל, אחרת תזכורות השעות לא יגיעו ליעד.

## 13. בדיקות קבלה בפרודקשן

הריצו את כל הרשימה לפני הכרזה על עלייה לאוויר:

- [ ] כניסה עם משתמש אדמין, משתמש מנהל ומשתמש עובד. כל אחד רואה רק את מה שמותר לו.
- [ ] יצירת פרויקט → חוזה → תת-חוזה עם אבני דרך. סכום החוזה מתקבל נכון.
- [ ] דיווח שעות: שבוע מלא, העתקה משבוע קודם, ניסיון דיווח בתקופה נעולה נחסם.
- [ ] הנפקת חשבון חלקי: שורות אבני דרך, מע"מ, עכבון, הצמדה. הסכומים תואמים לחישוב ידני.
- [ ] הורדת ה-PDF: עברית מיושרת לימין, לוגו, חתימה, וסימן מים בטיוטה.
- [ ] שליחת החשבון במייל לעצמכם. הגיע לתיבה, לא לספאם, ה-PDF מצורף.
- [ ] רישום תקבול והקצאתו לחשבון. היתרה הפתוחה קטנה בהתאם.
- [ ] דוח יתרות חוזים וייצוא ל-Excel.
- [ ] העלאת מסמך והורדתו חזרה דרך הקישור החתום.
- [ ] `ניהול → יומן שינויים` מציג את כל הפעולות עם שם המשתמש.

**בדיקת ה-Cron** ידנית (כל משימה מחזירה `{"ok":true}`):

```bash
curl -H "Authorization: Bearer $CRON_SECRET" https://app.pgl.co.il/api/cron/cbs-index-fetch
curl -H "Authorization: Bearer $CRON_SECRET" https://app.pgl.co.il/api/cron/invoice-aging
curl https://app.pgl.co.il/api/cron/period-lock          # ללא הסוד – חייב להחזיר 401
```

## 14. לוח הזמנים של המשימות האוטומטיות

Vercel Cron פועל ב-UTC בלבד, ולכן השעה בישראל זזה בשעה בין קיץ לחורף:

| משימה | UTC | שעון ישראל (קיץ / חורף) |
|---|---|---|
| תזכורות שעות | 06:00 יומי | 09:00 / 08:00 |
| חשבונות ריטיינר | 03:00 יומי | 06:00 / 05:00 |

## 16. יום ה-Go-Live

1. **הקפאה:** הודיעו למשתמשים על שעת סיום העבודה באדמירל.
2. **ייצוא אחרון:** ייצאו מאדמירל את הנתונים שהשתנו מאז ההגירה הראשונה וייבאו אותם.
3. **התאמה:** השוו בין המערכות שלושה מספרים – סך החוזים, סך החשבונות שהונפקו, וסך היתרות הפתוחות. אסור שיהיה פער.
4. **פתיחה:** שלחו למשתמשים את הקישור ואת `docs/user-guide-he.md`.
5. **אדמירל לקריאה בלבד:** השאירו אותו נגיש לקריאה לפחות שלושה חודשים.
6. **מעקב צמוד בשבוע הראשון:** בדקו כל בוקר את מסך ההתראות, את יומן השינויים ואת לוג ההרצות ב-Vercel.

**תוכנית נסיגה:** אם מתגלה תקלה חוסמת ביום הראשון, חוזרים לעבוד באדמירל, מתקנים, ומריצים את ההגירה מחדש. כל עוד לא הונפקו חשבונות חדשים מהמערכת אין נזק בלתי הפיך. מהרגע שהונפק החשבון הראשון, נסיגה מחייבת ביטול ידני שלו.

## 17. תחזוקה שוטפת

- **שדרוג גרסה:** מיזוג ל-`main` מפעיל פריסה אוטומטית. אם הגרסה כוללת שינוי סכמה, הריצו `pnpm db:migrate` מיד לאחר מכן.
- **מדד המחירים:** המשיכה מהלמ"ס אוטומטית בין ה-15 ל-20 בחודש. ודאו מדי חודש שהערך נקלט, ואם לא, הזינו ידנית בהגדרות ההצמדה.
- **שינוי שיעור מע"מ:** מוסיפים שורה חדשה בהגדרות המע"מ עם תאריך תחילת תוקף. אין לערוך שורה קיימת.
- **החלפת סודות:** החליפו `CRON_SECRET` ומפתחות API אחת לשנה, ואז Redeploy.
- **ניטור:** הגדירו `SENTRY_DSN` כדי לקבל דיווח על שגיאות שרת, ובדקו את לוג ה-Cron ב-Vercel אחת לשבוע.
